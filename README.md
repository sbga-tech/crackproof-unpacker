# CrackProof Unpacker

A static, evidence-driven unpacker for CrackProof-protected Windows PE files. The design prioritizes **robustness and compatibility** over sample-specific shortcuts: it discovers candidate structures, replays bounded combinations, accepts only a uniquely authenticated result, reconstructs a normalized PE, and verifies that result before an atomic write. It does not execute protected code or require a runtime hook or driver.

## Supported

The unpacker has passed 75 samples from games dated from 2018 through 2026.

### Image types and formats

- PE32/I386 and PE32+/AMD64 protected images.
- Native executables with authenticated I386 CRT, I386 standalone, AMD64 import-handoff, or AMD64 unwind-based startup paths.
- Native AMD64 DLLs and managed DLL/EXE images; managed output uses a verified semantic CLR entry container.

### Packer variants

- Payload stored in the main file or in a matching `<input>._` sidecar.
- Payload-block plans recovered by native staged-controller or evidence-search providers.
- Identity, fixed, generated byte-map, and nested fixed-point transform families.
- AES-CBC plus the supported custom compression/decoding families.
- Encoded loader imports or retained standard PE imports, with validated exports, TLS, resources, exception/debug metadata, and base relocations where recoverable.

The unpacker fails closed when descriptors, decryption chains, startup semantics, imports, or output provenance are missing or ambiguous.
Reconstructed files are normalized for correctness and may not be byte-identical to a runtime image or another unpacker's output.

## Build

Rust 1.96 or newer is required.

```sh
cargo build --release
```

The executable is written to `target/release/crackproof-unpacker`.

## Usage

```text
crackproof-unpacker [OPTIONS] <INPUT> [OUTPUT]
```

```sh
# Write an explicit destination
target/release/crackproof-unpacker protected.exe recovered.exe

# Omit OUTPUT to write protected_unpacked.exe
target/release/crackproof-unpacker protected.exe

# Reconstruct and verify without writing
target/release/crackproof-unpacker --dry-run protected.exe

# Emit detailed crackproof-event/v1 JSONL on stdout
target/release/crackproof-unpacker --events protected.exe recovered.exe > events.jsonl
```

Options:

- `--dry-run`: rebuild and verify in memory; cannot be combined with `OUTPUT`.
- `--events`: emit detailed JSONL events on stdout.
- `--silent`: emit nothing on success and one fatal JSON object on failure.
- `-h`, `--help`: show command help.
- `-V`, `--version`: show the version.
